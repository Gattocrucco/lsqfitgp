# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Project

lsqfitgp — a general purpose Gaussian process regression module in JAX, integrated with `gvar` (Gaussian error propagation) and `lsqfit` (nonlinear least-squares fits). The manual is in `docs/` and is published at https://gattocrucco.github.io/lsqfitgp/docs.

## Commands

All our development commands are make targets. All make targets use `uv run` under the hood. Run `make` to list them.

## Directory layout

We often use a worktree-first layout where the directory lsqfitgp/ is not a worktree, while each subdirectory lsqfitgp/foo, lsqfitgp/bar, etc. is a worktree. When started from a subdirectory, stay there, and don't try to read/access stuff outside of the worktree.

## Workflow

To check the code you write:
- `make lint`
    - cheap to run, unleashes all linters on everything
    - don't show your work without this first!
- `make setup` if needed
    - this installs the pre-commit hooks and checks python and jax work fine
    - cheap to run (cached), does not clean, idempotent
- run the unit tests relevant to your code changes with `uv run pytest ...`
    - not all tests right away because the full test suite takes a while to run
- at the end of debugging, run the full test suite to check everything works
    - use `uv run pytest -n 4`; `make tests` does the same but also saves coverage
    - skip this if you think the focused tests were sufficient for a surgical change
- when changing/writing documentation for public stuff, or code used by the examples:
    - `make examples docscode docs` runs the examples and the code snippets in the manual (which also produce the figures in the manual), then builds the html documentation
    - check the html documentation is fine
- do not update changelog, we write it before release

## Architecture

**Source layout:** `src/lsqfitgp/`. Public modules only re-export the public symbols from private implementation submodules (names starting with `_`); `lsqfitgp/__init__.py` defines the public namespace, plus the public subpackages `copula` and `bayestree`.

| Module | Role |
|---|---|
| `_patch_jax.py`, `_patch_gvar.py` | modify global state on import: enable `jax_enable_x64`, register `gvar.BufferDict` as a jax pytree, make gvar work with jax functions. Imported first in `__init__.py` |
| `_GP/` | the `GP` class, built from mixins: `_elements.py` (define processes and points: `defproc`, `addx`, `addtransf`, `addcov`, ...), `_processes.py` (transformations of processes: `deftransf`, `defderiv`, ...), `_compute.py` (inference: `prior`, `pred`, `marginal_likelihood`, `decompose`) |
| `_Kernel/` | kernel base classes (`CrossKernel`, `Kernel`, stationary/isotropic variants), algebra (`_alg.py`), linear operations like derivatives and rescalings (`_ops.py`), and the decorators used to define kernels (`kernel`, `stationarykernel`, ...) |
| `_kernels/` | the library of concrete kernels (`ExpQuad`, `Matern`, `Wendland`, `BART`, `Celerite`, `AR`, ...) defined with the decorators of `_Kernel` |
| `_linalg/` | matrix decompositions of covariance matrices (`Decomposition`, `Chol`), Toeplitz algorithms, sequential algorithm framework |
| `_fit.py` | `empbayes_fit`, empirical Bayes fit of hyperparameters by maximizing the marginal likelihood |
| `_array.py` | `StructuredArray`, a jax-compatible imitation of numpy structured arrays, used as input points with multiple fields |
| `_Deriv.py` | `Deriv`, specification of derivatives w.r.t. named variables |
| `_gvarext/` | `gvar` extensions: jacobians, gufunc wrapping, formatting of uncertainties (`uformat`, `gvar_format`) |
| `_jaxext/` | jax utility extensions (ufunc wrapping, batching, hashing) |
| `_special/` | special functions implemented in jax (Bessel, zeta, gamma, exponential integrals, ...) |
| `_fastraniter.py` | `raniter`, `sample`: fast sampling of multivariate Gaussians |
| `copula/` | reparametrize probability distributions as transformations of Normal variables, for use as gvar priors |
| `bayestree/` | `bart` and `bcf`: BART-like nonparametric regression with the `BART` kernel |

**Data flow:** define a `GP` with a kernel → add points/processes (`addx`, `addtransf`, ...) → `prior` gives gvars, `pred` conditions on data → optionally `empbayes_fit` to fit kernel hyperparameters, which calls `GP.marginal_likelihood` under jax autodiff.

Other directories:
- `tests/`: the unit tests, with a structure that mirrors the source
- `examples/`: example scripts, run by `make examples` through `examples/runexamples.py`; the figures they produce are shown in the manual
- `docs/`: the sphinx manual; `docs/runcode.py` (run by `make docscode`) executes the code blocks in the `.rst` files, and some `.rst` files are generated by the `.py` scripts next to them
- `config/`: scripts used by the make targets and the pre-commit hooks

## VCS style

- **Commit messages**
    - <= 50 characters wide description
    - <= 72 characters wide body
    - conventional commits style
- **PR description**
    - study the diff, don't just trust the commit messages (since stuff may have been reverted or altered over the course of development)
    - reason about what is the main purpose of the PR and open with that
        - understanding a description is easier if it opens with the point
        - don't just list all changes mechanically
    - keep it short, short, short
    - no hard wrap, each paragraph on one physical line (github UI preserves source newlines, let it soft wrap instead)
    - don't include a "test plan". you are not going to actually follow it anyway
    - remember to include your "Generated with ..." attribution footer

## Code style

- **Formatter/linter:** ruff with single quotes
- **Imports:** inside the package, import sibling modules (`from . import _linalg`) and use them qualified (`_linalg.Chol`)
    - for some heavily used big (sub)modules, e.g., `from jax import numpy as jnp`, `from jax import random; random.foo` is preferred to `from jax.random import foo, foo1, foo2, ..., foo999999`.
- **Headers:** all source files carry a GPL-3 license header
    - the first line is a comment with the path of the file, `lsqfitgp/<path relative to src/>` for files in the package, `lsqfitgp/<path relative to the repository>` otherwise (checked by `make lint`)
    - the copyright notice lists the years, e.g. `Copyright (c) 2022, 2023, 2024, 2026, Giacomo Petrillo`
    - when creating a new file, use only the current year for the copyright notice
- **docstrings:**
    - numpydoc convention, rendered with the sphinx `numpydoc` extension
    - types are documented in the docstring (`x : array`), not with type annotations in signatures
    - class docstrings and `__init__` docstrings are concatenated in the documentation
    - keep docstrings short, don't fill them with implementation details
        - related: no redundant comments, if the code is readable, it's self-documenting
        - docstrings and comments shall be _timeless_, not a narration of the development work
        - again, BE BRIEF, humans read slower than you!
    - keep private/internal docstrings short or absent if they are so already
- **jax** conventions:
    - the library runs with `jax_enable_x64` on, floats are float64 by default
    - kernels and GP computations must work both with numpy and jax arrays, and under `jit`/`grad`, because `empbayes_fit` differentiates through them
    - don't cast to jax arrays things which are already jax arrays (e.g., notice previous casts)
    - avoid explicit jax types if not necessary, e.g., do `jnp.ones(shape)` instead of `jnp.ones(shape, jnp.float64)`
    - try to unify code paths by clever usage of array indexing/broadcasting/axes, e.g., `x[..., i]` will work both if x is 2d or 1d
    - use `array.item()` to cast a size-1 array to a scalar python type
- other **python** conventions:
    - use dicts as if they were frozendicts when possible: e.g., do `d = dict(d, a=1, b=2)` to set values instead of `d['a'] = 1` or `d.update(a=1)`, safer
        - related: prefer tuples to lists
    - prefer `if ...: return; else: return` to early returns
        - if-else block are much easier to read visually for a human, even if redundant due to returns
        - of course for some cases it's obviously super-convenient to return early from a big function, should be clear when it happens
- **WORKAROUND markers:** we support comments like `# WORKAROUND(jax<99): remove this patch when we bump jax to v99`, enforced by `make lint` checking the oldest supported version of the package
    - also works with python versions

## Testing

- pytest, we use parametrization and test classes with inheritance a lot (e.g., `tests/kernels/test_kernels.py` defines a test class per kernel)
- tests import helpers with `from . import util`, so pytest uses the default (prepend) import mode
- fixtures in `tests/conftest.py`:
    - `rng`: a numpy random generator with a deterministic per-test seed; always use this (or `key`) instead of hardcoded seeds
    - `key`: a deterministic per-test jax random key
    - `cached`: caches expensive reference values in `tests/cached/`
    - autouse fixtures reset the gvar global covariance matrix and the global random seeds at each test
- to compare arrays, use the `assert_` functions in `tests/util.py` (e.g., `assert_close_matrices`, `assert_allclose` with zero default tolerances, `assert_same_gvars`)
    - use `rtol` in test comparisons, add `atol` only if necessary (comparison of values that are near zero on some relevant scale)
- `util.tryagain` re-runs a flaky test, `util.xfail`/`util.skip` mark inherited test methods on a specific subclass
- `make tests` runs the tests in parallel with pytest-xdist; `NPROC=0` disables it
- `make tests-old` runs the tests with the oldest supported python and dependencies; use `ARGS` to pass options to pytest, e.g., `make tests-old ARGS='-n0 -k test_pigs_fly'`
